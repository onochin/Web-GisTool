# Web-GisTool：ベクターファイル変換ツール追加依頼

既存プロジェクト

onochin/Web-GisTool

に、3つ目のツールとして
「ベクター変換」
を追加してください。

このWeb-GisToolは、

「QGISやCLIを起動しなくても、ブラウザだけで簡単なGIS処理を行う」

ことを目的としています。

今回も処理は可能な限りブラウザ内で完結させ、
アップロードしたGISファイルを外部サーバーへ送信しない構成としてください。


# 1. 今回の目的

ベクターファイルを画面へドラッグ＆ドロップし、

1. 入力形式を自動判定
2. CRSを可能な限り自動判定
3. 必要な場合だけ追加設定
4. 出力形式を選択
5. ブラウザ内で変換
6. 変換済みファイルをダウンロード

できるシンプルなツールを作成してください。

今回はVectorのみ実装します。

Raster変換は実装しません。

ただし、将来的に同じ「ファイル変換」ツールへRasterを追加し、
Vector / Rasterの自動判定結果に応じて出力形式候補を切り替えられる構造を意識してください。


# 2. ツール名・ルート

Dashboard上の表示名：

ベクター変換

候補ルート：

/vector-converter

既存の

src/config/tools.ts

へツール定義を追加してください。

既存Dashboardのカード生成方式をそのまま利用し、
Dashboardへ直接ハードコードしないでください。


# 3. 対応形式 v1

まず以下の4形式を対象としてください。

入力：

- GeoJSON
  - .geojson
  - .json

- KML
  - .kml

- Shapefile
  - .zip
  - .shp単独ではなく、原則ZIPとして扱う
  - ZIP内の .shp / .shx / .dbf を認識
  - .prj / .cpg があれば利用する

- GeoPackage
  - .gpkg
  - Vector Feature Tableのみ対象


出力：

- GeoJSON
- KML
- Shapefile ZIP
- GeoPackage


CSV / TSVは今回は実装しなくて構いません。

まずGISベクター形式同士の変換を安定させることを優先してください。

# 5. ファイルをドロップしたら自動解析

ファイルをドロップしたら、

- ファイル名
- ファイル形式
- Vectorであること
- CRS
- EPSG
- Geometry type
- Feature数

など、変換に必要な最低限の情報を取得してください。

既存GIS Infoには、

analyzeGisFile()

およびCRS判定処理があります。

同じファイルについてGIS Infoとベクター変換ツールが
別々の判定ロジックを持たないようにしてください。

可能な限り、

src/lib/gis/
src/lib/crs/
src/lib/files/

にある既存ロジックを再利用・共通化してください。


# 6. 入力形式による自動判定

拡張子だけでなく、
可能な範囲でファイル内容も確認してください。

例えば、

sample.json

でもGeoJSONとして正しく認識できること。

ZIPの場合は、
ZIP内部を確認してShapefileかどうか判定してください。

GeoPackageはSQLite / GeoPackageとして認識してください。

判定できない場合は、
勝手に形式を推測して変換せず、

「対応していない形式、またはファイルを判定できません」

と表示してください。


# 7. GeoPackage入力

GeoPackageは複数レイヤーを持てるため、
ここを特別に扱ってください。

.gpkg をドロップした場合、

GeoPackage内のVector Feature Tableを取得し、
レイヤー一覧を表示してください。

例：

レイヤー
[ 道路 ▼ ]

複数レイヤーの場合は、
変換するレイヤーを1つ選択します。

v1では、

「GeoPackage全レイヤーをまとめて別形式へ一括変換」

は不要です。

1回の変換につき1レイヤーで構いません。


# 8. GeoPackage出力

GeoPackageを出力形式として選択できるようにしてください。

例：

GeoJSON
↓
GeoPackage

出力時には、

レイヤー名
[ roads ]

のような入力欄を必要な場合だけ表示してください。

初期値は元ファイル名または元レイヤー名から生成してください。

v1では、

- 1 GeoPackage
- 1 Vector Layer

で構いません。

以下は対象外です。

- GeoPackage Raster Tile
- Style
- QGIS独自設定
- Relation
- その他のGeoPackage拡張

Vector Feature Tableの変換に集中してください。


# 9. CRSの扱い【重要】

このツールの主目的は
「ファイル形式変換」
です。

そのため、CRSは可能な限り維持してください。

ただし、出力形式の仕様上必要な場合は変換してください。


## GeoPackage / Shapefile

入力CRSを維持できる場合は、
原則として同じCRSを維持してください。


## GeoJSON

RFC 7946準拠のGeoJSONとして出力する場合は、
WGS84 / longitude, latitude
として出力してください。

任意投影座標をそのまま
RFC 7946 GeoJSONとして書き出さないでください。


## KML

KMLもWGS84 longitude / latitudeとして出力してください。


したがって例えば、

JGD2011 / 平面直角座標 IX系 GeoPackage
EPSG:6677

↓

KML

の場合は、

EPSG:6677
↓
WGS84

へ座標変換してからKMLを生成してください。


# 10. 既存座標変換ロジックを再利用

Web-GisToolには既に座標変換ツールがあります。

CRS変換が必要な場合、
新しい変換ロジックをベクター変換ツール内へ重複実装しないでください。

既存の

src/lib/crs/
src/lib/coordinates/

等の変換ロジックを確認し、
再利用してください。

必要なら共通APIとして整理してください。


# 11. CRSが不明の場合

入力データのCRSが不明で、

出力時に座標変換が必要な場合は、
勝手にWGS84と仮定しないでください。

例えば、

CRS：不明

EPSGを指定
[        ]

のように、
必要なときだけ手動EPSG入力欄を表示してください。

既存のCRS resolverを利用してください。

未登録EPSGの場合は、
適切なエラーを表示してください。


# 12. 出力形式によるUI切替

選択した出力形式に応じて、
必要な設定だけ表示してください。

例：

GeoJSON
→ 特別な設定なし

KML
→ 特別な設定なし

Shapefile
→ 必要な警告だけ表示

GeoPackage
→ レイヤー名


入力GeoPackageで複数レイヤーがある場合だけ、

レイヤー選択

を表示してください。

常に大量の設定項目を表示しないでください。


# 13. Shapefile入力

Shapefileは複数ファイルで構成されるため、
v1ではZIP入力を基本としてください。

ZIP内に最低限、

.shp
.shx
.dbf

があることを確認してください。

あれば、

.prj
.cpg

も利用してください。

複数のShapefileが1つのZIPに含まれている場合は、
可能であればレイヤー一覧を表示してください。

実装負荷が高い場合は、
v1では

「1 ZIP = 1 Shapefile」

という制限でも構いません。

その場合はUIとREADMEへ明記してください。


# 14. Shapefile出力

Shapefile出力は必ずZIPでダウンロードしてください。

少なくとも、

.shp
.shx
.dbf

を含めてください。

CRSが分かる場合は、

.prj

も生成してください。

日本語属性を扱う場合は、
可能であればUTF-8を示す

.cpg

も含めてください。


Shapefileには、

- フィールド名長
- 属性型
- 文字コード
- Geometry制約

などGeoPackage / GeoJSONより古い制約があります。

情報が失われる可能性がある場合は、
黙って変換せずユーザーへ警告してください。


# 15. 属性情報

可能な限り属性を維持してください。

最低限、

- 文字列
- 整数
- 小数
- 真偽値
- 日付系

について、
入力と出力で不必要に値を失わないようにしてください。

特に日本語フィールド名・日本語属性値をテストしてください。


# 16. Geometry

最低限以下を対象にしてください。

- Point
- MultiPoint
- LineString
- MultiLineString
- Polygon
- MultiPolygon

GeometryCollectionについては、
利用ライブラリや出力形式の制約を確認してください。

完全対応できない場合は、
対応外として明確に警告してください。

Z座標についても、
出力形式が対応する場合は可能な限り保持してください。

M値など保持できない値がある場合は、
黙って削除せず警告してください。


# 17. 同一形式の変換

入力形式と出力形式が同じ場合は、
原則として変換ボタンを無効にするか、
その形式を出力候補から除外してください。

例：

GeoJSON → GeoJSON

は通常の形式変換としては不要です。

ただし将来的に
CRS変換やデータ正規化用途で利用する可能性はあるため、
内部設計上は強く依存させないでください。


# 18. ダウンロード

ブラウザからファイルをダウンロードできるようにしてください。

例：

sample.kml

sample.geojson

sample.geojson

sample.gpkg

Shapefileの場合：

sample.zip

# 20. ライブラリ追加について

現在のpackage.jsonを確認し、
既存ライブラリだけで実装できる部分は再利用してください。

GeoPackage、Shapefile等の処理には
追加npmパッケージが必要になる可能性があります。

新規依存を追加する場合は、
いきなり大量にインストールせず、

まず以下を報告してください。

- 候補パッケージ名
- 何に使用するか
- ブラウザ対応の有無
- メンテナンス状況
- ライセンス
- おおよそのbundleへの影響
- 他の候補との比較

依存は必要最小限にしてください。

特に巨大なGDAL/WASMを安易に導入せず、
今回のVector変換に必要な機能に対して
より軽いライブラリで十分かを最初に検討してください。

ただし、GeoPackage・Shapefile・KMLを安定して扱う上で
WASM等が合理的であれば、その理由を説明してください。

依存追加方針を示した後に実装を進めてください。

# 25. エラー処理

以下を適切に処理してください。

- 壊れたファイル
- 空のファイル
- 未対応形式
