# webgis-tools 初期実装依頼

## WebGIS Tools Dashboard ＋ 汎用座標変換ツール

Webブラウザ上で利用できるGISユーティリティ集 `webgis-tools` を作成してください。

将来的には、座標・測地、ベクタ処理、空間解析、ジオメトリ処理、データ確認、WebMapなど、さまざまなGISツールを追加し、トップページを「WebGIS Tools Dashboard」として利用する予定です。

現段階では、将来実装するツールの種類を固定しません。

今回は、

1. WebGIS Tools Dashboard の基盤
2. 最初のツールとして「汎用座標変換ツール」

を実装してください。

座標変換ツールは、

「緯度経度 → 平面直角座標」

だけに限定せず、

**変換元CRS → 変換先CRS**

を指定して任意の対応CRS間を変換できる構造としてください。

# 3. 座標変換ツールの基本思想

このツールは、

**CRS A → CRS B**

という汎用的な座標変換ツールとして設計してください。

例：

* WGS84 → JGD2011
* WGS84 → Web Mercator
* WGS84 → JGD2011 / 平面直角IX系
* JGD2011 → JGD2011 / 平面直角IX系
* 平面直角IX系 → WGS84
* 平面直角IX系 → Web Mercator
* Web Mercator → JGD2011
* 平面直角の系間変換

などです。

React UI内に個別変換ロジックを作るのではなく、

「変換元CRS」
↓
「共通座標変換エンジン」
↓
「変換先CRS」

という構造にしてください。

# 7. EPSG定義の扱い

proj4はすべてのEPSGコードを番号だけで自動認識するわけではないため、この点を曖昧にしないでください。

最低限、今回の標準プリセットで使用する

* EPSG:4326
* EPSG:3857
* EPSG:6668
* EPSG:6669～6687

については確実に使用できるよう、必要なCRS定義を登録してください。

CRS定義は一元管理してください。

例えば：

src/
lib/
crs/
definitions.ts
presets.ts
resolver.ts

などです。

EPSG直接入力については、CRS resolverを経由する構造としてください。

将来的に対応EPSGを増やしたり、外部CRS定義サービス等を利用したりできるように、

UIから直接 `proj4.defs()` を操作する構造にはしないでください。

第一版で未登録EPSGコードが入力された場合は、

「このEPSGコードは現在このツールに登録されていません」

など、明確なエラーを表示してください。

不明なCRSを推測して変換しないでください。

# 8. CRS情報モデル

CRS情報はTypeScriptの型として管理してください。

最低限、以下を保持できる構造を検討してください。

* EPSGコード
* 表示名
* 短い表示名
* CRS種別

  * geographic
  * projected
* 単位

  * degree
  * metre
* 座標軸情報
* プリセットカテゴリ
* proj4定義
* 日本の平面直角座標系の場合は系番号

例：

```ts
type CrsDefinition = {
  code: string;
  epsg: number;
  name: string;
  shortName: string;
  type: "geographic" | "projected";
  unit: "degree" | "metre";
  axisOrder: ...;
  proj4?: string;
  planeRectangularZone?: number;
};
```

実際の型設計は、より良い方法があれば変更して構いません。

# 9. 座標軸の扱い【非常に重要】

座標軸を曖昧にしないでください。

特に以下の3種類には注意してください。

---

## Geographic CRS

WGS84やJGD2011では、

一般的なGIS処理やProj4js内部では通常、

* x = longitude
* y = latitude

として処理します。

一方、EPSG定義上の軸順序や一般ユーザーの表記では、

* latitude
* longitude

と表現される場合があります。

UI表示と内部処理を混同しないでください。

---

## Web Mercator

基本的に、

* x = Easting
* y = Northing

です。

単位はmです。

---

## 日本の平面直角座標

日本の測量で使用する平面直角座標では、

* X = Northing（北方向）
* Y = Easting（東方向）

です。

これは非常に重要です。

UIには明確に、

`平面直角座標：X＝北方向、Y＝東方向`

と表示してください。

一方、Proj4js内部では通常、

* x = Easting
* y = Northing

として扱います。

したがって、日本の平面直角座標をUIからProj4jsへ渡す際には、

UI：

`[X, Y] = [Northing, Easting]`

内部：

`[x, y] = [Easting, Northing]`

という変換が必要になります。

この入れ替え処理をReactコンポーネント内へ分散させないでください。

専用の座標正規化関数を作成してください。

---

# 10. 内部座標の正規化

内部では座標順序を統一してください。

例えば、

地理座標：

`[longitude, latitude]`

投影座標：

`[easting, northing]`

などです。

UIへの入力・出力時だけ、対象CRSに応じた表示順序へ変換してください。

以下のような責務分離を検討してください。

* UI座標 → internal coordinate
* internal coordinate → proj4
* proj4 result → internal coordinate
* internal coordinate → UI座標

特に日本の平面直角座標について、

X/Yの入れ替え処理を1か所へ集約してください。

# 14. 表示精度

地理座標：

緯度・経度を小数点以下8～10桁程度まで確認できるようにしてください。

投影座標：

m単位で小数点以下3桁程度まで確認できるようにしてください。

ただし、

**表示用丸めと内部計算値を分離してください。**

変換を繰り返した際に表示用丸め値によって精度を失わない設計にしてください。
